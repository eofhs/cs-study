# 🌐 Wireshark 실습: HTTP GET 요청 패킷 및 OSI 계층 분석

### 1. 실습 개요
- **도구:** Wireshark
- **대상 사이트:** `neverssl.com` (HTTP 평문 통신 분석)
- **목표:** 단일 HTTP GET 패킷(Frame 630)을 통해 L2~L7 계층 구조와 원시 바이트(Hex/ASCII)의 대응 관계 파악

---

### 2. 패킷 헤더 계층별 분석 (OSI 7 Layer)

| 계층 | 프로토콜 | 주요 정보 및 분석 |
| :--- | :--- | :--- |
| **L1** | **Frame** | • 캡처된 전체 크기: 502 bytes<br>• Wi-Fi 무선 인터페이스를 통해 수신됨 |
| **L2** | **Ethernet II** | • **Src MAC:** `88:f4:da:86:54:0c` (내 PC Wi-Fi 무선 랜카드)<br>• **Dst MAC:** `00:08:52:00:00:01` (공유기/기본 게이트웨이 Davolink)<br>• *핵심:* L2 통신은 로컬 구간(Next-Hop) 전송이므로 최종 웹 서버 IP와 무관하게 Dst MAC은 게이트웨이 주소가 됨 |
| **L3** | **IPv4** | • **Src IP:** `10.10.31.135` (사설 IP)<br>• **Dst IP:** `34.223.124.45` (neverssl.com 웹 서버 공인 IP) |
| **L4** | **TCP** | • **Src Port:** `49192` (임시 포트)<br>• **Dst Port:** `80` (HTTP 기본 포트)<br>• 페이로드(HTTP 데이터) 크기: 448 bytes |
| **L7** | **HTTP** | • **Request Line:** `GET / HTTP/1.1`<br>• **Host:** `neverssl.com`<br>• **Connection:** `keep-alive` (연결 유지)<br>• **User-Agent:** Windows 10, Chrome 브라우저 환경<br>• **Accept-Language:** `ko-KR` (한국어 선호) |

### 3. 패킷 바이트 창 (Hex & ASCII View) 분석
네트워크 선로를 흐른 실제 0과 1의 바이너리 데이터를 1바이트씩 표현한 창.

- **구조:** `오프셋(시작 번지) | 16진수 바이트(Hex) | 아스키 문자(ASCII)`
- **대응 관계:**
  - `0030` 번지의 `47 45 54 20` ➡️ ASCII 문자 **`GET `**
  - `2f 20` ➡️ ASCII 문자 **`/ `**
  - `0d 0a` ➡️ 줄바꿈 기호(`\r\n`)이며 오른쪽에는 출력 불가 제어 문자라 `··` 점으로 표시됨
- **특징:** 암호화되지 않은 HTTP 프로토콜은 모든 헤더와 본문 텍스트가 바이트 창에 그대로 노출됨.

### 4. 실습 중 해결한 의문점 (Q&A)

**Q1. 스마트폰이나 PC의 충전 단자(C타입 등)에도 MAC 주소가 있는가?**
- 아니다. MAC 주소는 물리 단자가 아니라 L2 프레임을 처리하는 **네트워크 어댑터(NIC 칩셋)**에 부여된다.
- 따라서 한 기기 안에서도 Wi-Fi 모듈, 블루투스 모듈이 각각 독립된 고유 MAC 주소를 가진다.

**Q2. 내부 사설 IP나 MAC 주소가 깃허브에 노출되어도 안전한가?**
- 안전하다. 사설 IP(`10.x.x.x`)는 외부 공용 인터넷에서 접근이 불가능하며, MAC 주소는 공유기(L3 라우터)를 통과하는 즉시 라우터의 MAC으로 교체되므로 외부 공격자가 악용할 수 없다.

**Q3. 목적지 서버 IP는 미국에 있는데, 왜 L2의 목적지 MAC 주소는 우리 집 공유기(Davolink)일까?**
- IP 주소는 통신의 **'최종 목적지(End-to-End)'**를 가리키지만, MAC 주소는 바로 다음 장비로 가기 위한 **'로컬 구간(Next-Hop)'** 전송에만 쓰인다.
- 내 PC는 외부 인터넷으로 직접 갈 수 없으므로 기본 게이트웨이(공유기)의 MAC 주소를 적어 프레임을 넘긴다.
- 이후 패킷이 라우터를 거칠 때마다 L2 MAC 주소는 다음 장비의 주소로 계속 교체된다.
